From a matrix to a verified QR factorization

A design matrix often appears in several related calculations: estimating coefficients, producing predictions, adding observations or changing the set of predictors. A QR factorization records its geometry in a form that can support each of these operations. Understanding what the factors contain is therefore useful before deciding whether to store an explicit orthogonal basis, retain only a triangular factor or keep the orthogonal transformations in compact form.

This chapter introduces those representations through the identities they satisfy. The examples check reconstruction and orthogonality separately, then examine the column-ordering convention used by pivoted QR. These checks provide a common basis for the update and regression examples that follow.

The examples use fastQR 1.1.6, ggplot2 for figures and knitr for tables. All code uses explicit fastQR:: or base:: namespaces because both packages export a function named qr. For the examples in this guide, use the accompanying verified source build described on the Overview page. No attachment with library(fastQR) is required below.

1 Full, thin and compact representations

Let \(X\in\mathbb R^{n\times p}\) have full column rank, with \(n>p\). Its thin factorization is \[ X=Q_1R_1,\qquad Q_1^\top Q_1=I_p, \] where \(Q_1\) is \(n\times p\) and \(R_1\) is nonsingular, upper triangular and \(p\times p\). The columns of \(Q_1\) are orthonormal; \(Q_1Q_1^\top\) is a projector and need not equal \(I_n\).

The full factorization completes \(Q_1\) to an orthogonal matrix by adding \(n-p\) orthonormal columns: \[ \begin{aligned} Q&=[Q_1,Q_2]\in\mathbb R^{n\times n}, & Q_2&\in\mathbb R^{n\times(n-p)},\\ R&=\begin{pmatrix}R_1\\0_{(n-p)\times p}\end{pmatrix}\in\mathbb R^{n\times p}, & X&=QR=Q_1R_1. \end{aligned} \] Here \(Q_1^\top Q_2=0_{p\times(n-p)}\) and \(Q_2^\top Q_2=I_{n-p}\), so \(Q_2\) spans the orthogonal complement of the column space of \(X\). The zero block in \(R\) contributes nothing to the product; the thin representation therefore suffices to reconstruct \(X\).

The orthogonal complement is needed for some operations on complete factors, but it contributes nothing to the reconstruction of the original design. Its storage can be substantial when \(n\) is much larger than \(p\), which motivates retaining the thin factors whenever the subsequent calculation permits it. A compact representation goes a step further by storing the Householder transformations that define Q and forming its columns only when requested.

The triangular factor \(R_1\) should also be distinguished from the symmetric cross-product matrix. An upper triangular matrix is not generally symmetric or positive definite; under full column rank, the positive-definite matrix is \(R_1^\top R_1=X^\top X\).

Task Function Representation
Work directly with \(Q\) and \(R\) fastQR::qr() Explicit factors; full or thin
Store Householder information compactly fastQR::qr_fast() Packed factorization, optionally pivoted
Extract factors from packed output qr_Q(), qr_R() Form only the factors needed
Retain a triangular factor only qrchol(), rchol() \(R\) satisfying \(R^\top R=X^\top X\)

1.1 Rank and rectangular shapes

The factorization identity itself does not require a unique least-squares coefficient vector. If a design has dependent columns, a triangular factor can still represent it, but solving an unpivoted triangular system with a zero diagonal is no longer the full-column-rank calculation derived above. A rank-revealing pivoted factorization separates that situation from an ordinary full-rank solve.

A wide design with \(p>n\) also admits an orthogonal factorization, with Q of size \(n\times n\) and R of size \(n\times p\). It cannot have full column rank, so its unpenalized coefficient vector is not uniquely determined by the fitted response. The qr() and compact qr_fast() interfaces support that representation; the thin-factor interface has a different input contract. Ordinary least-squares interfaces retain their full-column-rank restrictions. Positive-penalty ridge fits also support wide designs; the chapter on ridge with growing designs develops this case through augmented least squares.

The declared numerical rank and the number of stored Householder transformations also serve different purposes. Extraction through qr_Q() and qr_R() follows their documented rank-dependent output rule. qr_Q_full() constructs the complete orthogonal transformation from the compact information when that full transformation is required.

2 A first reproducible example

We generate a modest, full-rank design so that the dimensions and checks are easy to inspect. complete = FALSE avoids constructing an unnecessary \(n\times n\) matrix.

set.seed(2026)
n <- 120L
p <- 6L
X <- matrix(rnorm(n * p), n, p)
thin <- fastQR::qr(X, type = "householder", complete = FALSE)
full <- fastQR::qr(X, type = "householder", complete = TRUE)
knitr::kable(data.frame(
  representation = c("Thin", "Full"),
  Q_rows = c(nrow(thin$Q), nrow(full$Q)),
  Q_columns = c(ncol(thin$Q), ncol(full$Q)),
  R_rows = c(nrow(thin$R), nrow(full$R)),
  R_columns = c(ncol(thin$R), ncol(full$R))))
representation Q_rows Q_columns R_rows R_columns
Thin 120 6 6 6
Full 120 120 120 6

The factorization has two distinct defining properties: multiplication of the factors reconstructs X, and the columns of Q have the required inner products. The checks below examine both properties. The full Q is compared with \(I_n\) through \(Q^\top Q\), whereas the thin Q is compared with \(I_p\) through \(Q_1^\top Q_1\). These different identity sizes are a direct consequence of the dimensions of the two representations.

The helper scales a matrix difference by the Frobenius norm of its reference. This makes discrepancies comparable across matrices with different overall magnitudes. Its denominator is bounded below by machine epsilon to avoid division by zero; for the nonzero reference matrices in this example it is the usual relative error. The same helper is reused when the design is updated.

relative_error <- function(actual, reference) {
  norm(as.matrix(actual - reference), "F") /
    max(norm(as.matrix(reference), "F"), .Machine$double.eps)
}
checks <- c(
  thin_reconstruction = relative_error(thin$Q %*% thin$R, X),
  full_reconstruction = relative_error(full$Q %*% full$R, X),
  thin_orthogonality = relative_error(crossprod(thin$Q), diag(p)),
  full_orthogonality = relative_error(crossprod(full$Q), diag(n)),
  Gram_identity = relative_error(crossprod(thin$R), crossprod(X)))
knitr::kable(data.frame(check = names(checks), relative_error = unname(checks)),
             digits = 16)
check relative_error
thin_reconstruction 2e-16
full_reconstruction 4e-16
thin_orthogonality 1e-16
full_orthogonality 4e-16
Gram_identity 2e-16 
stopifnot(max(checks) < 1e-10)

These are checks of the defining identities. Comparing two implementations’ entries of \(Q\) and \(R\) directly would be misleading: paired column/row sign changes can produce equally valid factors.

2.1 Recovering a least-squares coefficient vector

Once the thin factors are available, the response enters through its projection onto the columns of Q. For a response \(y\in\mathbb R^n\), define \(c=Q_1^\top y\). The least-squares coefficient vector satisfies \(R_1\widehat\beta=c\), so a complete calculation needs a matrix-vector product followed by a triangular solve. Writing \(R_1^{-1}c\) is a mathematical identity, but an implementation can obtain the result without constructing an inverse.

The following response combines a linear signal with a deterministic perturbation. The perturbation makes the residual nonzero, allowing us to check its orthogonality to the fitted column space as well as the coefficient calculation. It is a numerical example, rather than a simulation of a particular observation-noise model.

demo_y <- drop(X %*% seq_len(p)) + sin(seq_len(n))
demo_projection <- crossprod(thin$Q, demo_y)
demo_coefficients <- backsolve(thin$R, demo_projection)
demo_fitted <- drop(X %*% demo_coefficients)
demo_residuals <- demo_y - demo_fitted
qr_derivation_checks <- c(
  coefficient_agreement = max(abs(demo_coefficients - lm.fit(X, demo_y)$coefficients)),
  fitted_projection = relative_error(demo_fitted, thin$Q %*% demo_projection),
  residual_orthogonality = max(abs(crossprod(thin$Q, demo_residuals))) /
    max(1, sqrt(sum(demo_y^2))))
stopifnot(max(qr_derivation_checks) < 1e-10)
knitr::kable(data.frame(check = names(qr_derivation_checks),
                        error = unname(qr_derivation_checks)), digits = 12)
check error
coefficient_agreement 0
fitted_projection 0
residual_orthogonality 0

The response projection has p entries, whereas the fitted response and residual have n. Multiplication by the thin Q maps between those coordinate systems. The near-zero value of \(Q_1^\top e\) verifies the defining least-squares geometry, while comparison with lm.fit() checks the resulting coefficients against a separate implementation.

3 Pivoting: keep track of the column order

Column pivoting changes the order in which the columns are factorized. With the permutation matrix returned by qr_pivot2perm(), the convention used here is \[ X=QRP,\qquad XP^\top=QR. \] Thus the correct Gram check is \(R^\top R=PX^\top XP^\top\), not generally \(R^\top R=X^\top X\).

Pivoting also changes the coordinates of the coefficient vector. If \(z=P\beta\), then \(X\beta=QRz\). The triangular solve therefore returns \(\widehat z\) in pivoted order; the original predictor order is recovered by \(\widehat\beta=P^\top\widehat z\). Restoring that order is necessary before interpreting individual coefficients or multiplying them by an unpermuted prediction design.

packed <- fastQR::qr_fast(X, pivot = TRUE)
Q <- fastQR::qr_Q(packed$qr, tau = packed$qraux,
                  rank = packed$rank, complete = FALSE)
R <- fastQR::qr_R(packed$qr, rank = NULL, complete = FALSE)
P <- fastQR::qr_pivot2perm(packed$pivot)
pivot_checks <- c(
  reconstruction = relative_error(Q %*% R %*% P, X),
  permuted_Gram = relative_error(crossprod(R), crossprod(X %*% t(P))))
knitr::kable(data.frame(check = names(pivot_checks), error = pivot_checks),
             digits = 16, row.names = FALSE)
check error
reconstruction 2e-16
permuted_Gram 1e-16 
stopifnot(max(pivot_checks) < 1e-10)
pivoted_coefficients <- backsolve(R, crossprod(Q, demo_y))
original_order_coefficients <- drop(t(P) %*% pivoted_coefficients)
pivot_derivation_error <- max(abs(original_order_coefficients - demo_coefficients))
stopifnot(pivot_derivation_error < 1e-10)

All subsequent update examples start from unpivoted factors, so that insertion and deletion positions refer directly to the original columns. Rank-deficient designs require additional care; the worked examples retain full column rank.

4 Triangular factors and linear systems

A triangular factor can be useful even when the subsequent calculation does not require an explicit orthogonal basis. The identity \(R^\top R=X^\top X\) provides the cross-product information through R, with storage proportional to \(p^2\). Two valid factors can have different row signs while satisfying the same identity, so agreement of the invariant is more informative here than equality of their entries.

The final part of the example solves a square system \(Au=b\), where \(A=X^\top X+I_p\). In this call, qrsolve(A, b) factorizes A and solves for u. It is distinct from directly computing least-squares coefficients by factorizing X and projecting a response. Adding the identity makes this demonstration system positive definite; its purpose is to show the solver interface on an easily checked calculation.

R_qr <- fastQR::qrchol(X)
R_only <- fastQR::rchol(X)
stopifnot(relative_error(crossprod(R_qr), crossprod(X)) < 1e-10,
          relative_error(crossprod(R_only), crossprod(X)) < 1e-10)

A <- crossprod(X) + diag(p)
b <- seq_len(p)
solution <- fastQR::qrsolve(A, b, type = "QR")
relative_error(A %*% solution, b)
## [1] 6.092069e-16
stopifnot(relative_error(A %*% solution, b) < 1e-10)

The square system above is deliberately well conditioned. Later examples distinguish factorization error from the sensitivity of a least-squares solution to an ill-conditioned design.
